# Архитектура и стек

Проект «Первый шаг» — персональный помощник для абитуриента и стажёра.
Кейс «Софтлайн Решения» · Цифровое наставничество и AI-менторство.

## Схема

```
Браузер пользователя                 Сервер (server.js)                 GigaChat API
┌──────────────────────────┐         ┌──────────────────────────┐       ┌──────────────┐
│ Голос (Web Speech API)   │         │ Хранит ключ авторизации  │       │ Языковая     │
│ или текст                │  POST   │ Получает и обновляет     │ HTTPS │ модель       │
│ Диалог-менеджер (этапы)  │ ─────►  │ OAuth-токен (30 мин)     │ ────► │ GigaChat-2   │
│ Сборщик промпта          │ ◄─────  │ Очередь запросов         │ ◄──── │              │
│ Разбор ответа, интерфейс │  JSON   │ Ограничение частоты      │       │              │
│ Память (localStorage)    │         │ Отдаёт страницу          │       │              │
└──────────────────────────┘         └──────────────────────────┘       └──────────────┘
          │
          └─ нет ключа или связи → упрощённый режим (правила + база знаний в браузере)
```

## Стек

| Часть | Технология |
|---|---|
| Интерфейс | HTML, CSS, JavaScript без фреймворков, один файл `public/index.html` |
| Голосовой ввод | Web Speech API (`ru-RU`). Запись идёт до нажатия «стоп»: при паузах распознавание перезапускается, текст склеивается |
| Озвучка ответов | Speech Synthesis API (включается в настройках) |
| Языковая модель | GigaChat API (тариф для физлиц), модель задаётся в `.env` |
| Сервер-посредник | Node.js 18+ без внешних библиотек (`server.js`) |
| Память | `localStorage` браузера: слабые и сильные стороны, ситуация пользователя, диалоги по режимам и сценариям |
| Экспорт | PDF через печать браузера, заметка в формате .txt |

## Как устроен ответ помощника

1. **Сборщик промпта** передаёт модели:
   - роль наставника и правила общения;
   - текущий этап разговора;
   - базу знаний со статьями под номерами;
   - банк кейсов сценария;
   - список типовых ошибок;
   - слабые зоны пользователя из прошлых сессий.
2. **Модель отвечает в JSON:** текст ответа, этап, признак завершённого кейса, разбор (`good`, `improve`, `example`), номера статей-источников, слабые и сильные зоны, найденные типовые ошибки, обезличенное описание ситуации пользователя и варианты быстрых ответов.
3. **Код обрабатывает ответ:** показывает сообщение и карточку разбора, а ссылки на источники подставляет сам по номерам статей. Поэтому модель не может выдумать источник. Затем код обновляет память о слабых зонах (этап 4).
4. **Упрощённый режим.** Если модель недоступна, помощник автоматически переходит на правила: распознаёт ключевые элементы ответа и типовые ошибки, показывает разбор и пример, отвечает из базы знаний.

## Этапы диалога в тренажёре

Знакомство → 4 проблемных кейса (каждый с каверзным вопросом и разбором) → итог → свободные вопросы.
Уже известную информацию о пользователе помощник не переспрашивает. Кейсы со слабыми зонами идут первыми.

## База знаний

- 3 сценария.
- 22 статьи, из них 6 — реальные случаи из СМИ и исследований.
- 15 кейсов для тренажёра, 13 типовых ошибок.
- 29 открытых источников:
  - официальные: Госуслуги, Трудовой кодекс РФ, правила приёма;
  - СМИ и исследования: hh.ru, Superjob, Газета.Ru, Т—Ж, Учёба.ру, «Профиль»;
  - площадки отзывов и форумы: Табитуриент, Dreamjob, вопросы юристу;
  - литература: Е. А. Климов, Н. С. Пряжников, Дж. Холланд (RIASEC), М. Уоткинс.

Полный список доступен в приложении: раздел «База знаний и источники».

## Безопасность и этика

- Ключ GigaChat хранится только на сервере (`.env`, исключён из репозитория через `.gitignore`).
- Сервер проверяет формат и размер сообщений и ограничивает частоту запросов: 20 в минуту с одного адреса.
- Личные данные не запрашиваются, данные пользователя не покидают его браузер, кроме текста диалога, который отправляется модели.
- Рекомендации помощника носят информационный характер и не заменяют официальные требования вузов и работодателей.
